# Putting the booth on your iPad

Everything here happens on this Mac and on the iPad. Nothing needs an App
Store submission, and nothing costs money unless you choose the paid route in
Step 8.

Work through it in order. Step 0 is the one that decides whether the rest of
the steps will work at all, so do not skip it.

---

## Step 0 — Check Xcode is new enough for your iPad

Usually fine, and worth thirty seconds to confirm. This Mac has:

| | |
|---|---|
| Xcode | **16.2** |
| iOS SDK | **18.2** |
| App's deployment target | **iPadOS 17.0** |

**On the iPad:** Settings › General › About › **Software Version**.

- **Same major version as the SDK** (any 18.x — including 18.5, newer than
  the SDK) → **fine, carry on.**
- **A whole major version ahead** (19.x, 26.x) → update Xcode from the Mac
  App Store first. It is a large download; start it before anything else.

### Why a newer *minor* version is fine

Since iOS 17 Xcode no longer needs a matching per-version device support
package. It mounts a single version-independent developer disk image through
CoreDevice:

```
/Library/Developer/CoreDevice/CandidateDDIs/iOS_DDI.dmg
```

(The `DeviceSupport` folder inside Xcode stops at 16.4 — that is the old
mechanism and is no longer what gets used.)

And building against an older SDK to run on a newer OS is simply the normal
forward-compatible case; it is how every App Store app works between Xcode
releases. A newer Xcode is only needed to *call* API introduced after your
SDK, and this app calls none.

A useful quirk: an **older iPad is easier here**, not harder. An iPad Air 3rd
gen tops out at iPadOS 17, well inside range. An iPad Air M1 will have been
offered every update since, so it is the one that could eventually drift a
major version ahead of this Xcode.

> If Xcode does object, it says so plainly — *"iPadOS N is not supported by
> this version of Xcode"* — at install time, and costs you nothing but the
> minute it took to find out. Try it before you download 10 GB.

## Step 1 — Add your Apple ID to Xcode

The app has to be signed before an iPad will run it. A **free** Apple ID is
enough — you do not need the $99/year Developer Program.

1. Open Xcode.
2. **Xcode › Settings…** (or `⌘,`)
3. **Accounts** tab → **+** → **Apple ID** → sign in.

Any Apple ID works, including the one you already use on the iPad.

## Step 2 — Open the project

```bash
cd /Users/seanamador/Movies/Work/CLAUDE/PhotoboothiPad && ./build.sh open
```

This regenerates `Photobooth.xcodeproj` and opens it. **Always open it this
way** — the project file is generated by `make_project.py`, so opening it
after adding source files keeps it in step.

## Step 3 — Set the signing team *(once, by hand — then never again)*

Do this **once**. Afterwards `make_project.py` keeps it, so regenerating the
project never loses it.

1. In Xcode's left sidebar, click the blue **Photobooth** project icon at the
   very top.
2. Select the **Photobooth** target.
3. **Signing & Capabilities** tab.
4. Tick **Automatically manage signing**.
5. **Team** → pick your name — it reads *Your Name (Personal Team)*.

Xcode now talks to Apple, creates the team record and issues your signing
certificate. That can take a few seconds.

### Why this cannot be automated away the first time

Xcode creates the Personal Team and the certificate only when a target asks
to be signed with them. Before that there is nothing on disk to read — no
team id, no identity — so no script can supply one. Picking it in the UI is
what brings it into existence.

From then on it *is* automatic: `make_project.py` reads the team out of
Xcode's accounts and writes it into the generated project, which matters
because the project file is regenerated and a hand-edit would otherwise be
wiped every time.

Confirm it stuck:

```bash
cd /Users/seanamador/Movies/Work/CLAUDE/PhotoboothiPad && python3 make_project.py && grep -m1 DEVELOPMENT_TEAM Photobooth.xcodeproj/project.pbxproj
```

A `DEVELOPMENT_TEAM = ...` line means you are done with this step forever.
To sign with a different Apple ID later, set `DEVELOPMENT_TEAM=XXXXXXXXXX`
in the environment.

**If the Team menu is empty**, the Apple ID did not finish signing in. Go
back to **Xcode › Settings › Accounts** and check your address is listed.

**If you see "Failed to register bundle identifier":** the id
`com.seanamador.photobooth.kiosk` is already claimed on another Apple ID.
Change `BUNDLE_ID` in `make_project.py` to something unique — a couple of
extra digits is enough — then re-run `./build.sh open`.

## Step 4 — Turn on Developer Mode on the iPad

iPadOS will not run a self-signed app until you allow it, and the setting is
hidden until the iPad has been plugged into Xcode at least once.

1. Connect the iPad to the Mac with a cable.
2. On the iPad, tap **Trust** when it asks, and enter the passcode.
3. On the iPad: **Settings › Privacy & Security › Developer Mode** → **on**.
4. The iPad **restarts**. Unlock it and confirm when it asks.

If *Developer Mode* is not in that list, leave the iPad plugged in, let Xcode
finish "Preparing iPad for development" (bottom of the Xcode window), then
look again.

---

## Step 5 — Build and run

One command, with the iPad plugged in and unlocked:

```bash
cd /Users/seanamador/Movies/Work/CLAUDE/PhotoboothiPad && ./build.sh ipad
```

It finds the connected iPad, builds, installs and launches. If there is no
signing identity or no device, it says which, and what to do about it, rather
than failing in a wall of build output.

Or do it from Xcode if you prefer: pick your iPad in the toolbar's device
menu (under *iOS Device*, not a simulator) and press **▶ Run** (`⌘R`).

First run takes a few minutes — Xcode copies a debug symbol package onto the
iPad. Later runs are quick.

Either way it installs and then stops with a message about an untrusted
developer. That is expected: Step 6 fixes it.

---

## Step 6 — Trust the certificate on the iPad

1. On the iPad: **Settings › General › VPN & Device Management**.
2. Under *Developer App*, tap your Apple ID.
3. **Trust** → **Trust** again.

Now launch **Photobooth** from the Home Screen. It will stay open.

## Step 7 — First launch

1. Tap **Allow** when it asks for the camera. Without this the booth has no
   picture; if you tap Don't Allow by mistake, fix it in
   Settings › Photobooth › Camera.
2. You should see the attract screen: `PHOTOBOOTH / SAY CHEESE / TAP TO START`.

**To reach the operator panel:** tap the **top-left corner** of the attract
screen **three times** within two seconds, then enter the passcode —
**`1234`** by default. Change it in Admin › KIOSK.

## Step 8 — Keep it alive past seven days

This is the part people get caught by at an event.

| Account | App keeps working for | Cost |
|---|---|---|
| **Free Apple ID** | **7 days** | — |
| **Apple Developer Program** | **1 year** | $99/year |

On a free account the app **stops launching after 7 days** and shows no
warning beforehand. Re-signing is just Step 5 again: plug in, press Run, done
in under a minute.

A free account also allows only **3 self-signed apps per device** at a time.

**If the booth is for a paid job, do Step 5 the morning of the event.** Do not
rely on a build from last week.

## Step 9 — Point it at the printer

In Admin › **PRINTER**:

1. **TARGET** → pick the right one:
   - **AIRPRINT (SELPHY)** — for the Canon SELPHY CP1500. Tap **CHOOSE**
     once, before the doors open, and no guest ever sees the iOS print sheet.
   - **THERMAL (WIFI)** — for the VOZY thermal printer.
   - *THERMAL (BLUETOOTH)* sends ESC/POS and is **wrong for the VOZY**, which
     speaks TSPL. It would connect, report success, and feed blank labels.
2. **PAPER** → the media you are actually loading.

### For the VOZY over wifi

The printer's "wifi" is an **HF-LPT270 serial bridge**, not a network printer.
It will never appear in the iOS print sheet — that is normal and is why this
path exists.

1. Put the printer into wifi mode.
2. On the iPad: **Settings › Wi-Fi** → join the **`HF-LPT270`** network. It is
   open by default, and it has **no internet** — that is expected.
3. In Admin, the defaults should already be right:

   | Field | Default |
   |---|---|
   | ADDRESS | `10.10.100.254` |
   | PORT | `8899` |
   | LABEL GAP | `2` mm (use `0` for a continuous roll) |
   | BAUD | `115200` |

4. Tap **CHECK**. You want **REACHABLE**.
   - **NO ANSWER** almost always means the iPad is on a different network.
5. Print one test label.
   - **Prints correctly** → done.
   - **Prints garbage or nothing** → BAUD is wrong. Open `10.10.100.254` in a
     browser (login `admin` / `admin`), read the UART baud the bridge is set
     to, and set the same number in Admin.
   - **Very slow** (a minute rather than ~5 seconds) → the bridge is running
     at 9600. Raise it on that same web page if the printer board allows it.

> **Secure it before an event.** The bridge's network ships **open**, so
> anyone in range could print to your booth. Put a WPA2 password on it from
> the same config page.

## Step 10 — Lock it down for guests

So a guest cannot swipe out of the booth:

1. **Settings › Accessibility › Guided Access** → on.
2. Set a passcode under *Passcode Settings*.
3. Open Photobooth, then **triple-click the top button** → **Start**.

Triple-click again and enter the passcode to leave.

Also worth doing: **Settings › Display & Brightness › Auto-Lock → Never**, and
keep the iPad on a charger.

## If something goes wrong

| What you see | What it means |
|---|---|
| *"iPadOS N is not supported by this version of Xcode"* | Only happens a whole major version ahead. Step 0. |
| *"Failed to register bundle identifier"* | Someone else's Apple ID has that id. Change `BUNDLE_ID` in `make_project.py`. |
| *"Unable to install — untrusted developer"* | Step 6. |
| App worked yesterday, now bounces off the Home Screen | The 7-day signature expired. Re-run `./build.sh ipad`. |
| Developer Mode missing in Settings | Leave the iPad plugged in until Xcode finishes preparing it. |
| *"Your team has no devices from which to generate a provisioning profile"* | Expected with nothing plugged in. A free team's profile must name a device, so Apple will not issue one until the iPad is connected. Plug it in and re-run. |
| Black rectangle where the camera should be | Camera permission was denied. Settings › Photobooth › Camera. |
| Printer says REACHABLE but paper is blank | TARGET is on Bluetooth/ESC-POS. The VOZY needs **THERMAL (WIFI)**. |
| Label prints as noise | BAUD mismatch. Step 9. |

---

## What this does not cover

**USB printing from the iPad.** It is not a setting you are missing — it needs
a DriverKit extension, an Apple-granted transport entitlement, and a TSPL
driver that does not exist. Use wifi for the VOZY and AirPrint for the SELPHY.

**Printing from Safari.** The browser build at `web/` cannot reach the VOZY on
any transport — no Web Bluetooth, no Web Serial, no WebUSB, no raw sockets.
Thermal printing is a native-app feature only.
